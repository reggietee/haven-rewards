# Google Sheets setup

Local IndexedDB and CSV exports work before Google credentials exist. The iPad never receives the service-account credential or excluded-person list.

1. In a Haven-controlled Google Cloud project, enable the Google Sheets API and create a dedicated service account. Create a JSON key and store it privately, outside this repository. Share a new private Google spreadsheet with the service-account email as Editor. Do not enable public/link sharing.
2. Create **Entries, Consents, Spins, Inventory, Audit, Excluded**, with exactly those case-sensitive names. Give each tab at least **10,000 rows and 19 columns**. The event uses sparse fixed row addresses, not appended rows. Do not sort rows in place, insert/delete rows, reuse this sheet for another kiosk, or clear UUID columns. Use filter views or exported copies for analysis.
3. Put the following headers in A1:S1 of each of the five general tabs:

```text
record_uuid | version | device_id | recorded_at | entity_id | entry_id | first_name | last_name | email | waitlist_choice | consent_text | consent_version | consent_source | prize_name | prize_code | unit_id | rules_version | duplicate_name | payload_json
```

The payload JSON preserves complete versioned source data, including event timezone, consent timestamp, acceptance text, prize values, full schedule snapshots and audit changes. Columns that do not apply to a tab remain blank. Entries contain identity/eligibility; Consents contain opted-in **and** not-opted-in proof; Spins contain outcomes and codes; Inventory contains the original schedule and later award/withdraw/restore events; Audit contains operator and completion events. UUID/row sequence creates idempotency; a timed-out successful request retries into the same row.

4. Configure **Excluded** privately:

| Column | Header | Purpose |
|---|---|---|
| A | exclusion_id | Private UUID |
| B | normalized_email | Optional email, trim/lowercase |
| C | first_name | Optional first name for full-name matching |
| D | last_name | Optional last name for full-name matching |
| E | active | TRUE enables matching; FALSE disables |
| F | operator_notes | Private notes, never read by the app |
| G | synced_record_uuid | Server-written review record UUID |
| H | device_id | Server-written device UUID |
| I | entry_id | Server-written entrant reference |
| J | review_flag | REVIEW or blank |
| K | checked_record_time | Source record timestamp |
| L | review_note | Operational explanation |

Populate A:F only. G:L are a separate server-owned table, indexed by the same queue sequence as Entries, and do not correspond to the person in A:F on that physical row. Matches use exact normalized email OR accent/case/punctuation-normalized first-and-last-name equality. Flags are for manual review, never automatic exclusion decisions. An offline entrant is checked on later synchronization. No match status is returned to the kiosk or normal CSV exports. A failure to read Excluded leaves the batch queued, rather than silently skipping review.

**Google Sheets tab protection and hiding do not provide read confidentiality.** Keep the entire operational spreadsheet restricted to staff authorized to see Excluded, protect the Excluded tab and G:L from accidental edits, and share only general CSV exports or carefully prepared copies with other people. Do not share this spreadsheet with entrants or general marketing users. Public sharing is never needed. The service account needs access to all tabs.

5. Set server-only variables in Vercel Production (and Preview only if intentionally using private test data there):

| Variable | Value |
|---|---|
| GOOGLE_SERVICE_ACCOUNT_EMAIL | JSON key client_email |
| GOOGLE_PRIVATE_KEY | JSON key private_key; literal newlines or escaped `\n` supported |
| GOOGLE_SHEET_ID | Spreadsheet ID from its URL |
| ADMIN_PIN_HASH | salt:scrypt hash generated by the setup script |
| SESSION_SECRET | At least 32 random bytes used to sign device grants |
| KIOSK_DEVICE_ID | UUID shown by controls in the **installed PWA on the real iPad** |

Never set `VITE_GOOGLE_*` or put JSON keys in public assets. Never paste credentials into bug reports, prompts or browser console. Keep `.env.local` private and use Vercel’s environment interface or CLI prompt to enter values.

6. Redeploy on the same temporary production origin before initialization. Authenticate the paired iPad. Readiness should show Sheets Configured. Use real-event controls only for the actual event; test studio never syncs. Test server integration using a separate private test Sheet and test configuration if pre-event live Google validation is desired. At the event, initialize and manually retry: the Inventory schedule and Audit initialization should appear, and last successful sync should update.

7. After the event, export all five tabs from the kiosk as well as a protected Google backup. A successful response acknowledges record UUIDs only. Investigate any “Row ownership conflict” without deleting local records or renumbering sequences. Reauthenticate if the seven-day grant has expired. Never initialize a replacement device against the same Sheet. A shared authoritative backend or deliberate audited recovery procedure is required for device replacement.

The application sends no email. Haven must apply its own approved retention period to IndexedDB, CSV copies and Google records and handle marketing unsubscribe requests outside this app.
